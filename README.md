# Automated Test Logging and Reports

Educational Python project focused on test execution logs and report generation.

## Focus

- Structured logging
- Test-result collection
- Report generation
- Improving traceability of automated checks

## Status

Completed learning project retained as part of my QA automation portfolio.

## Why test reporting matters / Зачем это нужно

[QA reports and failure triage](docs/qa-reporting-and-triage.md) describes structured logs, synthetic test evidence, status classification, reproducibility and follow-up.

Use this alongside [Quality Engineering Lab](https://github.com/KonstantinOreshnikov/web-testing-page-object) and [Python Learning Lab](https://github.com/KonstantinOreshnikov/python-lessons-geekbrains). A test report is useful to a team only when the underlying execution and assertion evidence exists.

**Evidence-led game QA example:** [Caribbean Merchant v1.0](https://github.com/KonstantinOreshnikov/KonstantinOreshnikov/tree/main/projects/caribbean-merchant) includes a [release QA report](https://github.com/KonstantinOreshnikov/KonstantinOreshnikov/blob/main/projects/caribbean-merchant/testing/original-qa-report.md) with 26 local Chromium scenarios and explicit unverified areas. This is a cross-project case study, not evidence that this repo's historic lesson scripts ran those scenarios.

The existing lesson scripts and sample log files are **historical**. They are not proof of current delivery, email operation or a completed automated test suite.
